# OUxSBLI システムアーキテクチャ

## 1. 概要

OUxSBLI は、NVIDIA GPU 上で高いパフォーマンスを発揮するよう設計された、モジュール式アーキテクチャを採用した GPU アクセラレーション対応の計算流体力学（CFD）ソルバーです。このシステムは、以下の 3 つの基本原則に基づいて構成されています。

1. **空間・時間分離**：離散化手法と時間積分処理を明確に分離
2. **GPUファースト設計**：CUDA Fortranカーネルを主体とし、CPUコードは連携処理をサポート
3. **精度の構成可能性**：コンパイル時に多階精度スキームを選択可能

## 3. モジュールの構成

### 3.1 ティア 1: 問題設定 (ケース固有)

**`mod_globals.f90`** (ケースごと)
- パラメータ宣言: 格子サイズ、スキームタイプ、精度階数
- GPU スレッド/ブロック構成
- 物理定数 (ケースによる)
- 役割: コンパイル時の設定

**`set.f90`** (ケースごと)
- 格子生成および座標系の設定
- 初期条件関数
- 境界条件の実装
- 役割: 問題の仕様

### 3.2 ティア 2: コア物理モジュール (共有)

**`mod_constant.f90`**
- 物理定数 (γ, R, Pr, など)
- 変換係数および数学定数
- 役割：グローバル物理パラメータ

**`calc_physical_quantities.f90`**
- 内部エネルギーからの温度
- 動粘度（サザーランドの法則）
- 音速
- 役割：基本変数の計算

**`set_coordinate.f90`**
- 曲線座標格子に対するヤコビアン行列
- 座標メトリック（∂ξ/∂x、∂η/∂y など）
- 格子間隔（dx、dy、dz）の処理
- 役割：格子メトリック計算

### 3.3 ティア 3：対流フラックス層

**`calc_keep_kernel_internal.f90`** (最適化されたKEEP)
- 2次/4次/6次KEEPカーネルの統合
- `calc_keep_x_in`, `calc_keep_y_in`, `calc_keep_z_in`
- フラックス関数用に 『calc_keep_3d.f90』 を呼び出す
- 役割：運動エネルギー保存型高精度スキーム

**`calc_slau_kernel_internal.f90`** (最適化SLAU)
- 多精度補間 (interp2/4/6)
- ウィグル検出器付き衝撃波適応型フラックス
- `calc_slau_x_in`, `calc_slau_y_in`, `calc_slau_z_in`
- フラックス関数用に 『calc_slau_3d.f90』 を呼び出す
- 役割：低散逸性衝撃波適応スキーム

**`calc_roe_kernel.f90`**
- 古典的Roe法
- 役割：衝撃波に対する堅牢なフラックス分割

**`calc_hybrid_kernel.f90`**
- KEEP/SLAU/Roeのハイブリッド切替
- 役割：スキームの適応的結合

### 3.4 ティア4：粘性およびLES層

**`calc_visc2.f90`**
- 2次粘性流束
- `calc_Ev2()`、`calc_Fv2()`、`calc_Gv2()`
- LES バリエーション: `calc_Ev_LES2()` など

**`calc_visc4.f90`**
- 4次（ME4-Base）粘性流束
- `calc_Ev4()`、`calc_Fv4()`、`calc_Gv4()`
- LES バリエーションが利用可能

**`calc_les.f90`**
- 大渦シミュレーション (LES) 乱流モデル
- 選択的混合スケール法
- 役割: SGS (サブグリッドスケール) 散逸

### 3.5 ティア 5: 境界条件

**`set_bc_common.f90`**
- すべての精度階数に対応した周期的（サイクリック）境界条件カーネル
- `set_bc_cyclic2()`、`set_bc_cyclic4()`、`set_bc_cyclic6()`
- LES変異同期: `set_bc_mut_common()`
- 役割: RKステージ後の境界条件適用

**`set_bc_tbl_sbli.f90`** (ケース固有)
- 乱流境界層用の壁境界条件
- SBLI用の斜め衝撃波境界条件
- 役割: 非自明な境界条件の実装

### 3.6 ティア6: 時間積分

**`calc_time_dev.f90`**
- RK3-TVD: `RungeKutta_3rd`, `RungeKutta_3rd_rescale`
- RK4: `RungeKutta_4th`, `RungeKutta_4th_rescale`
- 役割: 時間ステップの調整

**`calc_rescale.f90`**
- SBLIのための平均流速の再スケーリング
- `calc_mean()`: 統計量の蓄積
- `step_rescale()`: 変換の適用
- 役割: 衝撃波・乱流の平衡状態の追跡

### 3.7 ティア7: 通信およびユーティリティ

**`cpu_gpu_mpi.f90`**
- GPUメモリを用いたMPI送信/受信
- CPUルート（ピン留めメモリ）：`CPU_MPI_SEND`、`CPU_MPI_ISEND`
- GPUルート（CUDA対応）：`GPU_MPI_SEND`、`GPU_MPI_ISEND`
- 役割：GPU-MPI抽象化レイヤー

**`calc_muscl.f90`**
- 補間のためのMUSCL再構成
- 役割：高次プリミティブの再構成

**`print.f90`**
- 出力フォーマットおよびI/O
- 役割：データのシリアライズ

## 4. データフローアーキテクチャ

### 4.1 状態の表現

```fortran
! 一次状態ベクトル
Q(1, i, j, k) = ρ         (密度)
Q(2, i, j, k) = ρu        (x方向の運動量)
Q(3, i, j, k) = ρv        (y方向の運動量)
Q(4, i, j, k) = ρw        (z方向の運動量)
Q(5, i, j, k) = E または p    (エネルギーまたは圧力、設定に依存)
```

### 4.2 フラックス計算パイプライン

```
入力: Q (保存量), T (温度)
  ↓
[対流フラックス]
  - KEEP/SLAU/Roe カーネル
  - 出力: E(5,nx-1,ny-2,nz-2), F(), G()
  ↓
[境界条件の適用]
  - set_bc_cyclic() カーネル
  ↓
[粘性フラックス]
  - calc_visc2/4() カーネル
  - 出力: E_v(), F_v(), G_v()
  - LES: mut, qc2 の寄与を加算
  ↓
[右辺の計算]
  - ∂Q/∂t = -(∂E/∂x + ∂F/∂y + ∂G/∂z)
  ↓
[Qの更新]
  - ルンゲ・クッタ法によるステージ更新
```

### 4.3 GPUメモリ階層

```
┌─────────────────────────────────────┐
│  ホスト (CPU) メモリ                │
```

## 5. デザインパターン

### 5.1 パラメータ選択パターン

**問題**: コードの重複を避けつつ、複数の精度レベルに対応するにはどうすればよいか？

**解決策**: Fortranの組み込み関数 `kind()` を使用して精度を指定する

```fortran
integer(kind=2), parameter :: id_accuracy = 0  ! 2次精度
integer(kind=4), parameter :: id_accuracy = 0  ! 4次精度
integer(kind=8), parameter :: id_accuracy = 0  ! 6次精度

! その後: io = kind(id_accuracy) / 3
! 結果: io = 0 (2次), io = 1 (4次), io = 2 (6次)
```

**利点**:
- 単一のソースコードで3つの精度オプションに対応
- コンパイル時の最適化（定数の削除）
- 実行時の分岐オーバーヘッドなし

### 5.2 共有メモリのタイリングパターン

**問題**: GPUカーネルはステンシル用に隣接する値をロードする必要がある

**解決策**: ステンシルアクセス用にオーバーラップを持たせてスレッドブロックを分割する

```fortran
! 6次ステンシルを持つKEEPカーネル
integer, parameter :: sx = threadsE%x + 2*io + 1

! 共有メモリのインデックス: -(io-1):sx*sy*sz-io
real(8), shared :: rho(-(io-1):sx*sy*sz-io)

! 読み込み: 各スレッドは自身の位置 ± ステンシル半径の位置から読み込む
do ii = it-io, threadsE%x+io+1, blockDim%x
  rho(ii + offset_yz) = Q(1, i_base+ii, j, k)
enddo
call syncthreads()

! 計算: 安全なスレッドのみがフルステンシルを使用
if (io+1 <= i .and. i <= nx-(io+1)) then
  flux = KEEP(rho(idx-io:idx+io+1), ...)
endif
```

**利点**:
- 効率的なキャッシュ利用
- メモリアクセスの結合
- グローバルメモリ帯域幅を10～100倍削減

### 5.3 マルチフェーズ計算パターン (SLAU)

**問題**: SLAUの補間とフラックスには、メモリ使用の連携が必要

**解決策**: 2つの同期フェーズに分割

```fortran
フェーズ1: 補間
  - ステンシルデータの読み込み：より大きな共有メモリバッファ
  - 左/右の状態の計算
  - 結果の書き込み：より小さな専用共有メモリ
  - sync_threads()

フェーズ2：フラックス計算
  - フェーズ1から共有メモリを再利用（解放済み）
  - 衝撃センサーの読み込み
  - SLAUフラックスの計算
  - 出力の書き込み
```

**利点**:
- 共有メモリの占有量を最小限に抑える
- スタックフレームのオーバーヘッドを回避する
- より高い占有率を実現する

### 5.4 GPU対応MPIのための抽象化

**問題**: すべてのシステムがCUDA対応のMPIを備えているわけではない

**解決策**: ランタイム選択によるインターフェース

```fortran
interface CPUGPU_MPI_SEND
  module procedure CPU_MPI_SEND, GPU_MPI_SEND
end interface

! id_gpu_mpi パラメータによって選択
if (id_gpu_mpi == 2) then
  call CPU_MPI_SEND(...)   ! メモリピン、ホストからのMPI
else
  call GPU_MPI_SEND(...)   ! ダイレクトGPU MPI
endif
```

**利点**:
- HPCセンター間の移植性
- 新しいシステム向けの最適化の機会

## 6. 実行モデル

### 6.1 タイムステップごとの実行

```
DO step = 1, nt
  │
  ├─ [ステージ1] RK係数 α₁
  │   ├─ calc_physical_quantities(Q → T, μ)
  │   ├─ calc_EFG_Euler(Q, T → E, F, G)
  │   ├─ calc_EFG_Visc(Q, T, μ → ΔE, ΔF, ΔG)
  │   ├─ 右辺の計算: dQ = -∇·Flux
  │   ├─ 更新: Q₁ = Qⁿ + α₁·dt·dQ
  │   └─ set_bc(), MPI_exchange() 非同期
  │
  ├─ [ステージ 2] RK係数 α₂
  │   └─ (Q₂ についても繰り返す)
  │
  ├─ [オプション] SBLI 再スケーリング
  │   ├─ calc_mean(Q_rescaled)
  │   ├─ MPI_sync_mean()
  │   └─ step_rescale(Q_rescaled → Q)
  │
  └─ [出力] npステップごとに
      └─ recal/ ディレクトリへのI/O
```

### 6.2 MPI ランク割り当て

```
ランク 0  ──GPU 0──┐
ランク 1  ──CPU──  └─ グループ 0
        ──GPU 0──┐
ランク 2  ──GPU──  │
ランク 3  ──CPU──  └─ グループ 1
        ──GPU 1──┐
ランク 4  ──GPU──  │
ランク 5  ──CPU──  └─ グループ 2

パターン: mygpu = myrank / 2
  偶数ランクは演算
  奇数ランクはI/Oのためのギャザー
```

## 7. パフォーマンスに関する考慮事項

### 7.1 GPU占有率

**目標**: メモリ制約のあるカーネルで50%以上の占有率

**チューニング**:
- スレッドブロックのサイズ (`threadsE`, `threadsF`, `threadsG` 経由)
- 共有メモリの使用量（通常、ブロックあたり 96 KB 未満）
- レジスタの負荷（`pgprof` で監視）

### 7.2 メモリ帯域幅

**ボトルネック**: E、F、G のフラックス配列それぞれに対する 5×(nx,ny,nz) 回の読み取り/書き込み

**最適化**:
- 共有メモリを使用すると 10～100 倍削減可能
- アクセスパターンの結合（CUDA C++のベストプラクティス）
- 許容範囲内で低精度を使用

### 7.3 負荷分散

**課題**: スキームごとにコストが異なる

**バランス調整方法**:
- ランクごとのグリッドサイズを均等にする（z方向の分解）
- KEEP ≈ SLAU ≈ Roe（同程度のFLOPS）と仮定
- LESは~20%のオーバーヘッドを追加する

## 8. 拡張ポイント

### 8.1 新しい空間スキームの追加

1. `calc_mynewscheme_kernel.f90`を作成する
2. 2D/3D GPUカーネルを実装する（x、y、z方向）
3. `calc_flux_base.f90`のディスパッチャに登録する

1. `set_bc_mynewbc.f90`で実装する

### 8.3 新しい後処理の追加

1. `print.f90`の出力フォーマットを変更する
2. `main.f90`内のチェックポイントI/Oループから呼び出す
